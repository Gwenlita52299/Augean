# ADR-0001：spec 是快照，测试是承重墙

- **状态**：已接受
- **日期**：2026-10-25
- **决策者**：fairy

## 背景

三个参考实现分成两派：clowder-ai 把 spec 长期入库，配 close gate 与归档；pstack 与 mattpocock/skills 认为 spec 是过程产物，工作落地后即弃（原文 "Treat it as disposable after the work ships."）。

本项目此前的 PRD 草稿取了「资产派」：spec 长期保留，靠状态机 + 归档 + 定期巡检治理。但这与一个更基本的事实冲突——**文档与代码不一致时，唯一可信的是可执行的东西**。资产派为此必须维持状态机、取代链、归档区、孤儿巡检四套机制，成本随文档总量线性增长，而收益只是「能读回当时的叙述」。

## 决定

采用快照派。**代码是 ground truth；spec 只在工作项存续期内有效。**

1. 工作项关闭时，spec 的每条 AC 必须已落成可执行测试（或显式标 deleted 并附 ADR）。
2. 之后 spec 退役，在动态保留期（见 [03-lifecycle](../prd/03-lifecycle.md) §4）到期后被**删除**。
3. 删除可逆——全文留在 git 历史里；仓库内只留一行墓碑（ID、删除日期、行为现在落在哪个测试/ADR）。
4. 长期记忆只保留三样：**ADR**（不可逆决策）、**GLOSSARY**（词汇）、**测试**（行为）。
5. 不设归档区。退役即走向删除。

## 理由

- **可靠性**：测试随代码一起演进，不会撒谎；文档不会随代码演进，一定会撒谎。选择记忆载体时，应优先选那个「不改就会失败」的。
- **成本**：快照派把治理成本压成两件事（关闭时核对 AC→测试、到期删除）；资产派需要四套机制长期运行。
- **总量可控**：保留期与产出频率成反比（03 §4），活跃文档总量被锁在常数附近，而不是单调增长。
- 放弃的选项好在哪：资产派确实能读回「当时为什么这么想」。但这类问题真正需要的是**决策**，不是**描述**——把它交给 ADR 更省。

## 后果

- 变得容易：文档总量有上界；找到行为直接看测试；不需要维护归档区与取代链。
- 变得困难：失去 spec 的叙述性回溯；迫使每个工作项在关闭前写测试，对纯体验类改动不友好；需要 close gate 硬卡。
- 需要后续跟进：为「无法落成测试的 AC」定义出口（见 [07 D3](../prd/07-open-questions.md)）。

## 重新考虑的条件

- 出现合规/对外承诺类需求，必须有文字凭证且不可依赖测试。
- 团队规模大到 ADR 不足以承载上下文，需要保留完整设计叙述。
- close gate 的 AC→测试核对通过率持续低于 60%，说明该团队并不写测试，快照派的前提不成立。
